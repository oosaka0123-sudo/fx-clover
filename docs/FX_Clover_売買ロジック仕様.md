# FX-Clover ポコニカル売買ロジック仕様

更新日: 2026-09-07

## 1. 目的

本書は、FX-Clover / ポコニカル監視・研究・通知システムで使用する売買ロジックを、根拠の種類ごとに分離して管理するためのSSOT（Single Source of Truth）である。

本システムは **実注文を行わない**。TRIGGERは売買注文ではなく、ショート候補の通知イベントとして扱う。

```yaml
orders_enabled: false
```

## 2. 区分ルール

本書では必ず以下のラベルを使用する。

- 【公式ルール】ポコ本人の公式ブログ / 公式YouTubeで確認できた内容
- 【設計仕様】監視・通知システム化のためにプロジェクト側で定義した内容
- 【研究仕様】検証用に隔離し、公式ルールへ自動昇格させない内容
- 【手動入力】公式の数値基準が未確定で、人間の裁量確認を残す内容
- 【未確認】公式資料から厳密な定義を確定できていない内容

研究結果や推測を、公式ルールとして扱ってはならない。

## 3. 対象市場と時間足

### 対象通貨

【公式ルール】
- GBPJPY
- ショート特化として扱う

### 監視時間足

【設計仕様】
- D1
- H4
- H1
- M15
- M5

### 実行足

【設計仕様】
- M5

M5は現行システムの実行足であり、「ポコニカルはM5必須」という意味ではない。公式資料ではM1の例も存在するため、M5固定はプロジェクト側の設計である。

## 4. 基本思想

【公式ルール】

ポコニカルでは、上位足の下降環境の中で、下位足に現れる最初の戻り売りを狙う。

重視する要素は次の通り。

- 上位足と下位足が下方向
- 推進波のあと
- 最初の戻し
- 中段レンジ
- Wトップ / ヘッドアンドショルダー系
- 右肩
- DMA
- MAの並び
- 下方向への値幅余地

単純な「DMA下抜け = 売り」ではなく、環境 → 推進 → 戻し → 形 → 右肩 → DMAトリガー、の順序を重視する。

## 5. 状態機械

【設計仕様】

```text
NO_TRADE
  ↓
WATCH
  ↓
READY
  ↓
TRIGGER
  ↓
SIMULATED_POSITION
  ↓
EXIT
  ↓
NO_TRADE
```

- STOPは状態ではなく価格属性
- EXITは終了イベント
- PARTIAL_TAKE_PROFITは部分決済イベント
- 残数量がある間はSIMULATED_POSITIONを維持
- TRIGGERは実注文ではなく通知候補

## 6. NO_TRADE

【設計仕様】

以下の場合はNO_TRADEとする。

- 上位足が下降環境ではない
- 方向感がない
- 戻り売り候補ではない
- 右肩候補になっていない
- WATCH条件に入っていない
- WATCH / READY後に上位足環境が崩れた

## 7. WATCH

WATCHという状態名とシナリオ分類は【設計仕様】。

### Scenario A

【公式要素を使った設計仕様】

H1などで、陰線実体がDMA3×3を下抜けて確定したあと、戻しを監視する。

```text
bearish body breaks DMA3x3
→ candle close
→ WATCH
```

### Scenario B

【研究仕様】

下降トレンド候補で、以下をWATCH候補として扱う。

- ボリンジャーバンド下抜け
- バンドウォーク
- 下抜け後の小さいローソク
- ぴよ
- ぴよだまり
- DMA3×3に守られる動き

【未確認】

上記をどのAND / OR条件で組み合わせるかは公式確定していない。

現行の自動H1 WATCH判定は研究用プロキシであり、公式ルールとは扱わない。

## 8. READY

【設計仕様】

戻り売り候補として、以下を確認する。

1. 中段レンジ
2. 低い位置の右肩
3. DMA25×5の内側
4. レートがDMA3×3より下
5. 下方向に邪魔なMAが少ない
6. 下方向への値幅余地がある
7. パーフェクトオーダー、または邪魔なMAがない
8. 上位足が下降環境

### 自動化しない項目

以下は現時点では【手動入力】または【未確認】とする。

- 中段レンジの正確な数値範囲
- 「低い右肩」の数値基準
- DMA25×5の「内側」の厳密な機械判定
- 邪魔なMAの距離基準
- 下方向の値幅余地の数値基準

これらを推測で固定してはならない。

## 9. エントリー位置

【公式ルール】

> エントリーはいつだってWフォーメーションの右肩

狙うのは天井そのものではなく、右肩の戻り売り。

### Wトップ

```text
上昇
↓
左側の山
↓
一度下落
↓
戻し
↓
右肩
↓
再下落
```

### ヘッドアンドショルダー

中央トップではなく右肩を狙う。

【公式ルール】
- 実際のトップを取りに行かない
- 右肩が完成する前から右肩形成を想定して待つ
- 上位足環境の中で形を見る

【未確認】
- 右肩の高さ許容差
- 左右時間差の数値基準
- ネックライン等の機械的数値定義

## 10. TRIGGER

【設計仕様】

READY後、M5で以下を確認する。

- 右肩形成中
- 上位足下降環境が継続
- レートがDMA3×3より下側
- 戻りが入る
- 陰線実体でDMA3×3を下抜け
- ローソク足確定を待つ

```text
IF
  higher_tf_downtrend
  AND ready_conditions_ok
  AND right_shoulder_area
  AND bearish_candle_closes_below_dma3x3
THEN
  TRIGGER_SHORT_NOTIFICATION
```

TRIGGER_SHORT_NOTIFICATIONは通知イベントであり、OrderSend等を呼んではならない。

### TRIGGER直前の再確認

【設計仕様】

READY成立後に時間経過で条件が崩れる可能性があるため、TRIGGER直前に再確認する。

- 上位足環境
- DMA
- 右肩
- MA配置
- 下方向余地

崩れていればTRIGGERしない。

## 11. 損切り

【公式ルール】

### Wトップ

- 左肩高値をストップ基準にする

### ヘッドアンドショルダー

- 中央トップ高値をストップ基準にする

【設計仕様】

ショート時はスプレッドを加える。

```text
stop_price = stop_anchor_price + spread
```

【手動入力】
- stop_anchor_price

【設計仕様】
- spreadが欠損している場合はTRIGGER拒否
- spreadを0として扱わない

## 12. 利確

【公式ルール】

一括決済ではなく、FEターゲットで段階的に軽くする考え方を使う。

候補:
- FE 127
- FE 161.8
- FE 261 / 261.8

【未確認】
- FEアンカーの厳密な取り方
- 261か261.8か
- 各ターゲットで何%決済するか

よって、現時点では機械的な固定値配分を公式ルールとして実装しない。

## 13. DMA EXIT

【設計仕様】

SIMULATED_POSITION中に、陽線実体がDMA3×3を上抜けて確定した場合、残数量をEXITする。

```text
IF
  simulated_short_position
  AND bullish_candle_closes_above_dma3x3
THEN
  EXIT_REMAINING
```

DMA3×3は公式で使われる要素だが、現行v1.23におけるこの決済の固定運用はプロジェクト側の設計仕様として扱う。

## 14. 障害物MA

【設計仕様】

下方向に障害物MAや強い価格帯が近い場合は、自動決済ではなく以下の警告を出す。

```text
EARLY_EXIT_ALERT
```

「近い」の数値基準は【未確認】。

## 15. STOPとFEが同一バーで到達した場合

【研究仕様】

同一バー内の到達順が分からない場合、保守的にSTOPを先に処理する。

未来足やバー後情報を使って有利な順番に書き換えない。

## 16. 同一バー再エントリー

【研究仕様 / 設計仕様】

EXITしたバーでは再エントリーしない。

次バー以降で再評価する。

## 17. ローソク確定タイミング

【設計仕様】

以下は確定足ベースで判定する。

- WATCH DMA判定
- READY判定
- TRIGGER
- DMA_EXIT

以下は価格ヒットで扱う。

- STOP_LOSS
- FE

## 18. 公式未確認項目

次の項目は、公式根拠が揃うまでUNKNOWN / 手動 / 研究として保持する。

- 中段レンジの正確な数値境界
- 右肩の数値比較式
- DMA25×5のinside判定
- 障害物MA / 下方向余地の数値基準
- H1 WATCHの厳密なAND / OR、期限、取消条件
- DMA適用価格
- dojiの公式扱い
- swing high / low選択法
- FEアンカー
- 261 vs 261.8
- 部分利確配分
- spread取得タイミング
- 部分利確後のBE移動 / stop移動
- XMサーバー時刻の正式変換

## 19. 安全境界

【設計仕様 / HARD RULE】

- 実口座注文機能を実装しない
- `orders_enabled: false` を維持
- `OrderSend` / `OrderClose` / `OrderModify` / `OrderDelete` を実行コードへ追加しない
- 未来足を候補選択・判定へ使わない
- 研究成績を公式勝率・ライブ性能として表示しない
- 公式未確認の数値条件を推測で固定しない
- 秘密情報・口座情報・Webhookを公開しない

## 20. 実装向け要約

```text
1. GBPJPYを監視
2. D1/H4/H1/M15で下降環境を確認
3. 推進波を確認
4. 最初の戻しを待つ
5. Wトップ/H&Sの右肩候補を待つ
6. 中段レンジ/DMA25×5/MA配置/下方向余地を確認
7. READY
8. M5で戻りを待つ
9. 陰線実体がDMA3×3を下抜けて確定
10. TRIGGER_SHORT_NOTIFICATION
11. STOP候補
    - Wトップ: 左肩高値 + spread
    - H&S: 中央トップ高値 + spread
12. FE127 / 161.8 / 261系で段階利確候補
13. 陽線実体がDMA3×3を上抜け確定
    → EXIT_REMAINING
14. 実注文は出さない
```

## 21. 変更管理

本書に新しい「公式ルール」を追加する場合は、必ず公式一次資料の根拠を確認してから更新する。

数値条件を追加する場合は、以下を区別する。

- 公式に数値が示されている → 【公式ルール】
- システム都合で決める → 【設計仕様】
- 検証用の仮説 → 【研究仕様】
- 人間の判断が必要 → 【手動入力】
- 根拠不足 → 【未確認】

不明点を推測で埋めない。
